# AnimeVost PWA — план проекта

Неофициальное веб-приложение для просмотра аниме с animevost.org.
Брат-близнец нативного Android-приложения (см. `C:\Users\вика\project_android\AnimeVost\project\PLAN.md`),
но самодостаточный: здесь вся документация PWA-версии. Нативный план нужен
только для истории Android-багов.

Дата старта: 12.11.2026.

---

## 1. Цель

Одна кодовая база → три платформы:
- **Android** — устанавливается из Chrome/Edge/Samsung Internet (нативная версия уже есть, PWA не заменяет её, а дублирует);
- **iOS** — Safari → «На экран “Домой”» (iOS 16.4+). Нативной iOS-версии НЕ будет (Mac + Xcode + 99$/год + ревью — не наш путь);
- **ПК (Windows/macOS)** — Chrome/Edge «Установить приложение» → отдельное окно.

## 2. Стек и принципы

- **Vite + React + TypeScript.** Никаких Next/Remix — приложение целиком клиентское.
- Бизнес-логика переносится из нативного проекта **как есть** (`src/api/*` — уже чистый fetch).
- UI переписывается на DOM: StyleSheet → CSS, компоненты RN → HTML.
- Все цвета/токены — ТОЛЬКО в `src/theme.css` (CSS-переменные). Ничего хардкодить в компонентах.
- Структура файлов повторяет нативную (`src/screens`, `src/components`, `src/api`, `src/db`) —
  чтобы параллельно читать оба проекта и правки в одном переносить в другой.
- Архитектура плеера и жестов повторяет нативную (см. §8).

## 4. Сеть и хосты (ПРОВЕРЕНО ЖИВЬЁМ 12.11.2026)

Ключевая находка дня — **прокси не нужен вообще**:

| Что | Хост | Статус |
|---|---|---|
| API | `https://api.animetop.info/v1` | ✅ CORS открыт (`Access-Control-Allow-Origin: *`, методы GET/POST/OPTIONS) — браузер ходит напрямую |
| **Видео** | `https://video.animetop.info/…/*.mp4` | ✅ **https работает** (206 Partial Content) — `<video>` играет напрямую, Range нативный |
| **Картинки** | `https://animevost.org/uploads/posts/…` | ✅ валидный сертификат, 200 OK, есть копии вплоть до 2020 года |
| Картинки (CDN сайта) | `static.openni.ru` | ❌ https-сертификат истёк (проверено curl: SEC_E_CERT_EXPIRED) — **в PWA НЕ используем** |

- API отдаёт `urlImagePreview` с хоста `static.openni.ru` — в `src/api/images.ts`
  переписываем host на `animevost.org` (путь `/uploads/posts/…` совпадает 1:1).
  Правило то же, что в нативном: **хост картинок правится в одном файле**.
- `?v2` в конце URL у сайта — просто cache-buster, не обязателен.
- CORS-заголовков у хоста картинок нет — для `<img>` не нужны. Кэширование
  постеров в service worker — через `fetch(..., { mode: 'no-cors' })`
  (opaque-ответы в Cache Storage кладутся и отдаются).
- Риск-заметка: источник тот же владелец, что и сейчас; если переедет пути —
  правим один файл `images.ts`. Фолбэк на `static.openni.ru` (http) НЕ делаем —
  mixed content браузер всё равно режет.
- **Расписание — единственное место, где прокси всё же нужен.** Главная
  animevost.org (там живёт HTML с блоками `raspisMon…Sun`) НЕ отдаёт
  `Access-Control-Allow-Origin` — проверено curl 12.11.2026 с заголовком
  `Origin`. В `src/api/schedule.ts` — цепочка попыток: прямая → allorigins →
  codetabs; 12.11.2026 оба публичных прокси лежали (522), поэтому расписание
  стартует на кэше и «первые пользователи без сети» увидят вежливую ошибку —
  как только какой-то прокси оживёт, обновление пойдёт само. Прокси правятся
  в одном месте — список `PROXY_BUILDERS` в `schedule.ts`. Парсер проверен
  на живом HTML — 7 дней с реальными тайтлами.

## 5. API (зеркало нативного, проверенные причуды)

- Формат ответа: `{ state: { status, count }, data: [...] }`; `getInfo` разворачивает единственный элемент.
- **`last` — GET** (`?page=&quantity=`), не POST.
- **`playlist` — POST (`id=`), возвращает ГОЛЫЙ МАССИВ** без обёртки data (нативный план §4, ловили дважды).
- `search` — POST, поля `name` / `gen` / `year`; кириллица — через URLSearchParams-энкодинг.
- `genres`/`years` — GET; у жанров фильтруем заглушку 'Жанр'.
- Поля тайтла: `title` = `«Русское / Original [N из M]»`, рейтинг = `rating/votes*2`,
  анонс = `'[Анонс]'` во второй части, таймер новой серии — только из `getInfo` (в `last` врёт).

## 6. Данные — IndexedDB (idb)

Схема зеркалит SQLite нативного (перенос 1:1):
- `lists` — встроенные (favorites, history, …) + пользовательские; `hidden`, `position`.
- `list_items` — снапшот тайтла (anime_id, title, preview, description, rating, votes, added_at).
- `history` — anime_id, episode, quality, position_sec, duration_sec, watched_pct, preview-снапшот.
- `settings` — ключ-значение (автопереход, тип перемотки, скрытые списки).
- Защита встроенных списков от удаления — та же логика, что в нативном `db/lists.js`.
- При установке PWA данные не чистятся (на iOS правило «7 дней» не действует
  для home-screen веб-приложений); дополнительно можно запросить
  `navigator.storage.persist()`.

## 7. Дизайн: адаптив телефон + ПК (ОБНОВЛЕНО 12.11.2026)

**Решение юзера: телефон — приоритет, ПК — пока 1:1 с телефоном.**
- Телефон: дизайн ДОСЛОВНО как в нативном Android-приложении (те же экраны,
  структура, токены). Эталон — PLAN.md нативного проекта.
- ПК: пока тот же макет — по центру колонка ограниченной ширины
  (~560px, как телефонный экран). Никакого отдельного ПК-дизайна сейчас.
- ОТЛОЖЕНО (вернёмся после готовности и обкатки телефонной версии):
  сайдбар вместо табов, сетка постеров 4–6 колонок, hero-страница тайтла,
  плеер с боковой панелью серий, поиск в шапке.

База — утверждённый телефонный макет нативного приложения. Тёмная тема
Netflix-стиль, акцент оранжевый (токены — из `theme.css`, копия нативного `theme.js`).

| Блок | Телефон (< 700px) | ПК (≥ 700px) |
|---|---|---|
| Навигация | нижние табы | те же нижние табы по центру, контент колонкой ≤ ~1000px |
| Ленты (Главная/Поиск/Расписание/Закладки) | 1 колонка карточек | сетка 2–3 колонки |
| Страница тайтла | вертикально: постер → Смотреть → инфо | 2 колонки: постер слева, инфо справа |
| Плеер | fullscreen; Android: fullscreen + orientation lock | вписан в окно, тёмная подложка; кнопки PiP и «во весь экран» |
| Чипы (списки/серии/жанры) | горизонтальная лента | та же лента, шире |

- Кнопка-закладка на странице тайтла — как в нативном (справа от
  «Новая серия»+«Жанры», без подписи, открывает CardModal).
- CardModal (избранное/списки/таймер) — та же логика, DOM-версия.
- Брейкпоинт `700px` — отправная точка; правим по факту на живых экранах.

## 8. Плеер

- Нативный `<video>`: **duration браузер знает сам** — костыль `probeDuration`
  (mvhd-парсер из нативного) НЕ переносится.
- Управление: центральная play + нижняя панель (две play-кнопки, как в нативном —
  юзер одобрил), prev/next, лента серий чипами, HD/SD, автопереход (настройка).
- Жесты: **тап/драг по линии прогресса** (пузырь времени + кружок, прыжок на
  отпускании), **двойной тап ±10с**, **горизонтальный свайп-перемотка**.
  Урок нативного (b53b084/ede01d1): жест линии должен быть неотчуждаемым
  (в DOM это проще — pointer events + `setPointerCapture`).
- Автоскрытие контролов ~4с при воспроизведении; на драге не прятать.
- **Ориентация**: Android — `screen.orientation.lock('landscape')` в fullscreen;
  iOS — lock не поддерживается, показываем подсказку «поверни телефон 🔄».
- MediaSession (локскрин/наушники), Wake Lock (экран не гаснет), PiP на ПК.
- Запись истории: `saveProgress(position, duration, finished)` в IndexedDB,
  полоска «досмотрено N%» в ленте Истории.
- Продолжение с последней серии/секунды — из истории (как в нативном).

## 9. PWA-обвязка

- `vite-plugin-pwa`: manifest (имя, иконки, theme `#0B0B0F`, standalone) +
  service worker (autoUpdate). Офлайн-оболочка: app-shell кэш; постеры —
  Cache Storage через no-cors; API/видео — НЕ кэшировать.
- Иконки: сгенерировать из постера/логотипа (маска Android + круглые iOS).
- Установка: на Android баннер-кнопка «Установить» можно с `beforeinstallprompt`.

- Каждое решение/баг фиксируем записью в §13 (дата, коммит, диагноз, фикс) —

  адрес API — только в `config.ts`.

## 12. Отличия от нативного Android-приложения

- БД: SQLite → IndexedDB (схема та же).
- Плеер: ExoPlayer → `<video>`; duration нативный от браузера.
- Нет NSC/cleartext/httpify — вся сеть на https (картинки через animevost.org).
- iOS: нет programmatic landscape lock (подсказка «поверни телефон»);
  Web Push только iOS 16.4+; ставить можно только из Safari.
- Тестирование: adb/uiautomator не нужен — devtools; на Android-устройстве —
  chrome://inspect.
- Push «новая серия» — вне скоупа первого релиза (нужен свой мини-бэкенд).
